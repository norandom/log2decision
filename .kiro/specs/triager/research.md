# Terminal framework research

18 November 2026. **Selected for the later SSH client: Taffy for pane layout, Ratatui for widgets and drawing, and Crossterm for terminal events.** The application owns search editing, focus and divider positions. It calls the same bounded Rust operations exposed through MCP. Framework selection is based on the upstream capabilities below. Terminal behavior and latency still need a project measurement.

| Candidate | What the project provides | Implication for `triager` |
| --- | --- | --- |
| Taffy + Ratatui + Crossterm | Taffy solves CSS Flexbox and Grid. Ratatui draws widgets into rectangles measured in terminal cells. Crossterm delivers key, drag and resize events. | Compute rectangles for the visible panes. The small geometry bridge can follow Ratatui's published example or use the existing `panes-ratatui` adapter after a compatibility check. [Taffy](https://github.com/DioxusLabs/taffy) · [Ratatui integration example](https://github.com/ratatui/ratatui/discussions/1933) · [Existing adapter](https://docs.rs/panes-ratatui/) · [Terminal backends](https://ratatui.rs/concepts/backends/) |
| Ratatui's built-in `Layout` and `Flex` | Constraints divide an area into rectangles. `Flex` places the remaining space. Ratatui separately documents application-level Taffy integrations. The registered `ratatui-flex` 0.0.0 package reserves the name and exposes no public API. | The selected dependency for Flexbox geometry is `taffy`. Native Ratatui layouts remain available inside individual widgets. [Ratatui layout](https://ratatui.rs/concepts/layout/#other-layout-approaches) · [Package status](https://docs.rs/ratatui-flex/latest/ratatui_flex/) |
| Dioxus TUI | Dioxus deprecated the original public TUI renderer. In September 2026 its team reported that Devin CLI uses a rebuilt Dioxus terminal renderer and identified Blitz and Dioxus Native as its investment priorities. Separately, a community repository publishes source for an interactive Blitz-based cell renderer. | The Devin announcement gives no public SDK release for that renderer. The community implementation has its own source and dependencies. The selected stack uses Taffy independently of the Dioxus UI framework. [Dioxus renderer status](https://dioxuslabs.com/learn/0.7/beyond/project_structure/) · [Maintainer announcement](https://dioxuslabs.com/blog/joining-cognition/) · [Community renderer](https://github.com/JakkuSakura/dioxus-tui) |
| Ink | React components, Yoga Flexbox, keyboard input and a window-size hook support a pane-based terminal UI. Ink 8 filters mouse reports out of `useInput`. | Viable as a TypeScript MCP client. Deployment adds a Node runtime, and draggable splitters need separate mouse-event handling. [Ink](https://github.com/vadimdemedes/ink) · [Ink 8 input and resize behavior](https://github.com/vadimdemedes/ink/releases/tag/v8.0.0) |

## Interaction and acceptance

Splunk documents a search bar, timeline, fields sidebar and event viewer. OpenObserve documents a time histogram, results table and record details. Keep these familiar entry points. Add a direct way to inspect *why* a record entered the analyst work set, including A/B/C membership, evidence and allocation. An analyst should be able to narrow to an overlap, open a record and return to the same query and cursor. [Splunk search views](https://help.splunk.com/en/splunk-enterprise/search/search-tutorial/10.6/part-3-using-the-splunk-search-app/exploring-the-search-views) · [OpenObserve log exploration](https://openobserve.ai/docs/user-guide/data-exploration/logs/logs/)

For the acceptance test, launch the TUI on the analysis host through `ssh -t`. Complete the drill-down using only the keyboard. Resize the search editor and field sidebar, shrink the terminal to 80×24 and widen it again. Check cell boundaries, focus, query, saved evidence and shell restoration. Test optional dragging on a terminal that forwards mouse events. Record geometry and redraw cost separately from indexed drill-down time. Use operation counters to confirm pane resizing triggers zero archive, scorer or model work. [OpenSSH manual](https://man.openbsd.org/ssh#t) · [Scale and performance gate](performance.md)
