# triager implementation plan

The owner approved starting the native terminal on 18 November using the MCP walkthrough as its behavioral contract. The parent project's archive readers, scoring and Venn policy already supply evidence. The terminal starts with retained reports. Direct archive-scale operation and interoperability with MCP need the service milestones below. [Requirements](requirements.md) · [Worked example](recipe.md)

Use the [shared end-to-end cases](../../../docs/qualification/triager-e2e.md) to compare the [design walkthrough](analyst-flow.md), native terminal and parent CLI. A discrepancy in population, coverage or order reopens the corresponding case in both specs. Task 1.2 adds a real MCP stdio client to these cases. Task 2.2 extends handoff to independent MCP and terminal clients.

- [ ] 3.3 Decide and test a model judge for the recommend producer (deferred from 2.1 by the owner, 2026-11-25).

## Implementation Notes

- 1.1: A scope's record ID is the original's first native position (file record number, packed archive position, store `seq`), because the archive reader hands out rows in another order once deduplication spills. Policy IDs derive from the path as given to the reader, selections record the canonical path, and the scope binds both: a report made under another spelling is refused with `PolicyPath`. A join streams to its callback, so on `Err` the caller must discard what it received. The summary returned by `open_file` and `open_archive` is the caller's to hold beside `Scope::held_bytes()`; `input_summary_bytes` and `archive_summary_bytes` give the figure. `join_keys` takes the source a score manifest records (`source_path`, `content_sha256`, `settings.entries`, `max_record_bytes`); reading that manifest into a source claim is left to 1.2. `MarkedInput::source_location` in `l2d-core` is now `pub`.
- 1.2: `Service::call` is the single entry for both adapters. Every share is held before allocating; `ADAPTER_FIXED_BYTES` (4 MiB) covers one request, one response, a page and the job table, and `too_many_values` must run before any parse of a request line. Record IDs are `r-<16 hex>`. `ScoreManifest::load` reads a `baseline score` manifest into a source claim for `join_keys`. `ZipBatches::disk_dedup` in `l2d-core` reports spill live; `Scope::open_archive_watched` takes the watcher. Both interrupt tests need the job still running when spill is seen, so on a much faster build they fail rather than pass vacuously.
- 1.3: Set tables and scores are `Table`/`Scores` in `service/tables.rs` with a memory or disk placement, read in 16,384-row blocks; `extsort::sort_file` is the bounded external sort. A selection the read refuses in memory is read again onto disk (`read_again_for_disk`). Reuse is in `ops.rs::prepared` and is bound to snapshot, model, scorer revision, population and the membership file's content hash. `test_heap.rs` is the shared counting allocator for unit tests. The scale gate is run with `tools/triager-scale/run.py` against a fixture regenerated from `generate.py` (seed in `manifest.json`); `service_memory` now takes about 220 s.
- 2.1: Refinements live in `service/refine.rs` and are files in the work directory; recommendation producers in `service/recommend.rs`. `issue` assembles the whole result and checks its fit before it asks the budget, spends the allowance, counts or changes the run; keep that order. Errors of refine and recommend jobs pass `Shared::scrub` in `service.rs` `work`. `HostConfig` gained `policies`, `encoder` and `patterns` (`PatternLimits`, CLI `--max-patterns`, `--max-text-bytes`); a refinement revision equals the `discover search` one only with the same limits. `test_heap` tests in `recommend.rs` measure the Venn read and the making of a batch against their charges.
