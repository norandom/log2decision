# Triager interface contract (proposed v1)

The `triager` skill teaches the operations below. One Rust service owns source identity, set algebra, resource admission, evidence and allocation. The MCP adapter (`l2d mcp`) exposes the shared protocol. The terminal workbench over the service (`l2d tui --requests FILE` or `--receipt R`, task 3.2) makes the same tool calls on a service in its own process, with the host options of `l2d mcp`: its views, allocations and receipts are those of an MCP client. The first native implementation, `l2d tui --demo` or `--report` and its `--json` projection, still supports bounded retained reports and native receipts. Interoperable MCP receipts and archive-scale paging use the acceptance cases below and in the [cross-spec test contract](../../../docs/qualification/triager-e2e.md).

## Transport and identity

The proposed MCP server uses local stdio. Advertise typed tools with JSON Schema input and output, validate inputs before scheduling work, return structured results and keep stdout for JSON-RPC. The configured project and disclosure profile belong to the host. A tool argument cannot widen either scope. The examples show application payloads inside `tools/call` and abbreviate opaque handles. [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) · [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

Every request carries `v: 1`. Handles resolve only within the issuing project and expected artifact kind. A snapshot binds source bytes or store revision, selected archive entries, parser settings, limits affecting interpretation and record identity. A record handle refers to a distinct original in that snapshot and preserves the native locators, duplicate occurrences and their count. The resolver verifies the mapping from first position, source path/text-based policy ID or store ID. Mixed snapshots, changed source interpretation and ambiguous joins produce explicit errors.

## Operations

| MCP tool | Arguments beyond version | Result |
|---|---|---|
| `triager_open` | One configured source reference or analyst-supplied allowed path with adapter and optional ZIP entry filters, or one saved receipt | Snapshot and admitted capabilities, or the saved immutable candidate view or final work set with its snapshot and artifact kind. Large scans can return a job. |
| `triager_select` | Snapshot, existing selection, or candidate view from `triager_compose(mode=view)` as scope, plus producer kind, version and parameters | Immutable selection with coverage, member counts, provenance and evidence references. Score accepts a frozen scorer plus threshold or top-k and tie rule. Filter accepts literal, glob, regex or frozen pattern. Recommend accepts Venn policy, local model or issued-batch submissions. |
| `triager_refine` | Selection/view and a typed action for drilling by region, field value or time bucket, listing, splitting or merging patterns, previewing a mask/regex, or finding nearby records from exemplars | Bounded preview, or new derived selection/refinement revision with parent, exact membership, changed counts and method. A wider search requires an explicit target scope. |
| `triager_compose` | Snapshot, `scope` (active parent, defaults to snapshot), named selection handles, expression tree and mode. Use `view` to reduce repeatedly, or `allocate` with ordering, review budget, reserves and audit seed to finalize. | A view returns an immutable candidate handle, parent and reduction counts. Allocate returns the final set, source flags, allocations and deferrals. Explicit audit or reserve scopes may extend beyond the candidate expression. |
| `triager_inspect` | Snapshot, selection, candidate view or final-set handle, projection and page controls | Typed overview, regions, histogram, fields, records, evidence or bounded lineage. Lineage identifies navigation parent, producing inputs and accessible retained branches. Record evidence requires a record handle from the specified scope. |
| `triager_save` | Candidate view or final-set handle and idempotency key | Durable receipt binding kind, source, parent, evidence and recipe revisions, exact membership and ordering. Candidate receipts retain an unallocated hunt. Final receipts also retain allocation and deferrals. |
| `triager_job` | Project-owned job handle and `status` or `cancel` | Phase, admitted limits, progress where known, refusal/error details or committed artifact. |

## Walkthrough

The [interaction design](analyst-flow.md) includes an offline, drivable example. Production reductions use their active parent's population as the denominator in both count units. For example, composing `D ∩ C` with `scope=D` measures the share of D kept. The operator can separately request its share of the root. An explicit `refine` on a field or time bucket uses the same parent rule.

The host registers `public-fixture` as an allowed local archive. The analyst has already selected the scoring model, Venn policy and the review budget for this recipe. The example references known-good fixture artifacts. Tool names are MCP tool names, not shell commands.

```jsonl

{"tool":"triager_select","args":{"v":1,"scope":"S","producer":{"kind":"filter","syntax":"glob","query":"*login*"}},"result":{"v":1,"set":"B","status":"ready"}}
{"tool":"triager_refine","args":{"v":1,"set":"B","action":{"kind":"patterns"}},"result":{"v":1,"refinement":"P","groups":9,"status":"ready"}}
{"tool":"triager_select","args":{"v":1,"scope":"S","producer":{"kind":"recommend","method":"venn","policy":"V1","membership":"investigate_or_review"}},"result":{"v":1,"set":"C","depends_on":["M1"],"status":"ready"}}
```

`in` and `out` mean evaluated membership. `not_evaluated` carries a reason such as outside producer scope, unsupported input, incomplete run or model abstention. Recommendation output also preserves the original Venn route and support reason. An explicit unsupported-review recommendation may be `in` even though its actionable score is absent. Union, intersection and difference use three-valued logic. For example, `in − not_evaluated` stays unknown. Regions expose evaluated overlap and unknown coverage separately. A Venn recommendation derived from the same scorer as A carries that dependency. Materializing F retains why each slot was filled, each eligible record deferred, and any audit member drawn outside the expression from the declared snapshot. Selecting a policy route and allocating budget are separate options.

For GenAI recommendations, select a bounded candidate scope and issue an immutable batch with projected evidence. A host model can submit only issued IDs from that batch. Validate duplicate and foreign IDs, submission size, outcome enum and expected batch revision. An omitted item remains unevaluated until a later revision supplies a judgment. Here is a submission.

```jsonl
{"tool":"triager_select","args":{"v":1,"scope":"B","producer":{"kind":"recommend","method":"issued_batch","action":"issue","limit":8,"projection":["excerpt"]}},"result":{"v":1,"batch":"G1","revision":1,"records":[{"id":"R1","excerpt":"login attempt"}]}}
{"tool":"triager_select","args":{"v":1,"scope":"B","producer":{"kind":"recommend","method":"issued_batch","action":"submit","batch":"G1","expected_revision":1,"model":"dev-provider/model@rev","prompt_revision":"p1","items":[{"id":"R1","outcome":"recommend","reason":"Repeated sign-in failures"}]}},"result":{"v":1,"set":"C2","producer":"dev-provider/model@rev","status":"ready"}}
```

Store provider/model identity, prompt revision, input projection/hash, completion coverage and proposal provenance. Record a caller-supplied model identity as caller-reported. Supported outcomes are `recommend`, `pass` and `abstain`. Only an explicit analyst review can create a reviewed label.

The [worked reduction](recipe.md) uses a different C predicate from the broad Venn routing example. For an issued-batch C in that recipe, `recommend` is in, `pass` is out and an abstention or an omitted record is indeterminate. D is the saved A-minus-B view. A producer run over D can issue several bounded batches under a cumulative evidence allowance. Collect their submissions server-side into one coverage revision. Verify common source, scope, model, prompt and run, deduplicate retries and surface conflicting submissions for an original as indeterminate. No batch submission outside D can fill coverage. The final call identifies the three populations explicitly. The `state` selector tests the persisted membership state, so it can deliberately select unknowns. The allocator counts each original once, processes the stated pools in order and records unused capacity when a pool runs short.

## Drill-down and limits

Default to 25 rows, at most 100 per page, at most 32 KiB UTF-8 per serialized MCP tool result (including any text fallback), and at most 1 KiB per projected excerpt. These are proposed transport defaults. Enforce both item and byte limits before writing a response. Clip excerpts on character boundaries and report clipping. The same limits cover aggregates, examples, reasons, schema-driven responses and error details. Continue pages with an opaque cursor bound to project, revision, view, predicate, sort and projection. Reject stale or incompatible cursors. A receipt reopens the saved view from its first page. Application result paging is explicit because MCP standard pagination applies to discovery lists. [MCP pagination](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination)

Region counts separate distinct originals and occurrences. Each child returns a reduction receipt with parent, in, out, unknown, retained share and completeness for each unit. Named reserve and audit pools can refer to explicit views, including unfamiliar records or a seeded sample of assessed passes outside the candidate expression. Persist those scopes and any spillover rule. Fields report typed counts, missing values and exactness or sampling/overflow. A histogram names its timestamp field, timezone, range, bucket width and missing-time count. With no trustworthy time field return `time_unavailable`. Drilling into a field, region or time bucket issues a derived view on the same snapshot. Use server-side scans/indexes for aggregates and never infer totals from a displayed page.

Field and time views read an occurrence projection (task 3.1). `triager_open` takes `projections` beside `source`, or with `snapshot` as an explicit re-scan, and runs one more admitted read of the verified source. A projection declares up to 8 fields, from `kv` (the record's `key=value`, keyed by the name, as the terminal's automatic extraction) or `entry` (a `capture` over the entry path), and a timestamp from `text` (the leading one), `kv` or `entry`, read as `iso8601` with `Z` or an offset or as a `date` at 00:00 UTC. `source`, the entry, is built in. A field retains its first `max_values` values in read order (default 10,000, at most 100,000) and counts the rest as overflow; a value over 256 bytes is invalid. A re-scan keeps every earlier declaration and refuses a name declared otherwise (`field_defined`, `time_defined`). `triager_inspect` view `fields` (with `field` and a cursor for values) and `histogram` (at most 100 buckets, `bucket_seconds` from a fixed list) run as jobs on the projection. A field or timestamp no projection declares returns `status: projection_missing` with the missing coverage, the estimated scope and scan cost and the exact `rescan` request, and schedules nothing. A projection that declares no timestamp is answered the same way (`missing.time`). A declared timestamp that no counted occurrence has a valid value of returns `status: time_unavailable` with the occurrences by archive entry as a labelled alternative. With values beyond the limit, a values page states `ranking_exact: false`: it ranks among retained values only. `triager_refine` actions `field` (`value` or `missing`) and `time` (`start` and `end`, or `no_time`) make a child view on the same snapshot. Its `counts` and `occurrence_counts` are of whole originals, as set algebra and allocation count them. Its `matching_occurrences` counts the parent's counted occurrences that pass, and later field and time views of it count only those. A value beyond the retained limit is refused (`value_not_retained`), and so is a value longer than a field keeps (`value_too_long`). Evidence of a record lists every occurrence once the snapshot is projected, each with `in_view`. The owner confirmed these names on 26 November.

A receipt reopened on a host that registers its source under the name the receipt states (`source.ref`), or, under private-local, still allows the retained path of a source opened by path, reads excerpts of its retained originals from that source (task 3.2). The reopen result says so in `source.attached` and `capabilities.excerpts`. Each excerpt is one admitted read that is refused, before a byte is used, when the archive's SHA-256 is not the receipt's. A public receipt takes only a source the host declares a public fixture. Selecting, refining and projections stay `source_not_retained`, because the reopened snapshot holds the saved originals, not the whole source.

## Admission, evidence and disclosure

Stream selected ZIP entries using existing readers. Charge scans, joins, aggregation, model work and page serialization against the project's admission and staging rules. Whole-history Venn/grouping operations can explicitly refuse larger inputs. Return a reason and actionable scope/limit with the refusal. Long calls can return `{"v":1,"status":"running","job":"J1"}`. Clients use `triager_job` to poll or request cancellation. Status distinguishes waiting, running, cancel-requested, cancelled, completed, interrupted and failed. The service reports committed results when cancellation races completion. Concurrent calls share host/NPU admission and project-scoped publication locks. [Project resource and archive contracts](../../../README.md#what-works-today)

Receipts include the expression, ranking, capacities, audit seed, producer identities and dependencies, inputs, rows considered, omissions and resource summary. Commit immutable artifacts atomically. Mutating or job-starting operations accept an idempotency key. A request with the same idempotency key and payload returns its original result or in-progress job. Reuse with a different payload conflicts. After interruption, recover committed artifacts or expose interrupted status with no partial final set. Reopening a receipt recovers recorded evidence and decisions without rerunning inference. Refreshing executes an explicit new run with a parent receipt and new identities when inputs or outputs change.

Private/local mode performs inference on the host and confines raw evidence to the approved local analyst or local-model client. A hosted development client may receive bounded fields from an explicitly declared public fixture through the public-development profile. Bind disclosure to the host configuration and source classification before issuing examples. The local server needs no cloud-provider credentials. Treat log content, terminal escapes and generated text as untrusted evidence. Use a safe display projection and retain original bytes or source references on the host.
